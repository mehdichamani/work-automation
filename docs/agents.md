# 🤖 راهنمای عوامل توسعه‌دهنده (Agents Rules & Guidelines)

این سند شامل قوانین، استانداردها و نکات مهمی است که تمام عوامل توسعه‌دهنده و هوش مصنوعی (AI Agents) باید هنگام کار روی پروژه **اتوماسیون اداری اروم شیشه ساچی** از آن‌ها پیروی کنند. رعایت این اصول به حفظ پایداری، امنیت و خوانایی پروژه کمک می‌کند.

---

## 📌 قوانین کلیدی و حیاتی

### ۱. زبان پیام‌های کامیت (Git Commits)
*   **قانون اجباری:** تمامی پیام‌های کامیت در سیستم گیت **باید با توضیحات کامل و به زبان فارسی** نوشته شوند.
*   **مثال صحیح:**
    ```bash
    git commit -m "افزودن قابلیت ثبت امضای دیجیتال پرسنل و اتصال به کارتابل نامه‌ها"
    ```

### ۲. امنیت اطلاعات و عدم هاردکد کردن اطلاعات حساس
*   تحت هیچ شرایطی نباید اطلاعات حساسی مانند کلیدهای خصوصی، توکن‌های JWT، اطلاعات کاربری پایگاه داده، توکن‌های پنل پیامکی یا کلیدهای رمزنگاری را در فایل‌های پروژه هاردکد (Hardcode) کنید.
*   همواره از متغیرهای محیطی (`process.env` در بک‌اند) استفاده کنید و مقادیر پیش‌فرض امن را در فایل `.env.example` مشخص کنید.

### ۳. اولویت تغییر در کدهای منبع (Source Code)
*   برخی از فایل‌ها ممکن است آرتفکت بیلد (Build Artifacts) مانند فایل‌های داخل پوشه `dist` یا بیلد نهایی کلاینت باشند.
*   هرگز فایل‌های کامپایل‌شده یا نهایی را به طور مستقیم ویرایش نکنید. ابتدا فایل منبع اصلی (مثلاً داخل `frontend/src/`) را تغییر داده و سپس با دستور مناسب آن را مجدداً بیلد بگیرید:
    ```bash
    npm run build --prefix frontend
    ```

### ۴. فرآیندهای خودکارسازی و مدیریت فرآیند (PM2)
*   این پروژه از **PM2** برای مدیریت سرویس‌ها در محیط عملیاتی و توسعه استفاده می‌کند.
*   اگر تغییری در تنظیمات سرور یا متغیرهای محیطی دادید، فرآیندها را از طریق PM2 بازنشانی کنید تا تغییرات اعمال شوند:
    ```bash
    pm2 restart ecosystem.config.js
    ```
*   برای سیستم‌عامل ویندوز، ابزار مدیریتی `manage.bat` بهترین راه برای هماهنگ کردن سرویس‌هاست.

## 🛠️ استانداردهای کدنویسی (Coding Standards)

### بک‌اند (Backend)
*   **Express Router:** مسیرها باید همواره دسته‌بندی شده و در پوشه `routes/` قرار گیرند.
*   **تأیید ورودی‌ها (Validation):** از `express-validator` برای اعتبارسنجی تمام داده‌های ورودی کاربر در تمامی APIها استفاده کنید.
*   **مدیریت خطا (Error Handling):** کلیه بلاک‌های کد باید دارای کنترل خطا با `try/catch` باشند و خطاها به صورت ساختاریافته به کلاینت بازگردانده شده و در صورت نیاز لاگ شوند.

### فرانت‌اند (Frontend)
*   **کامپوننت‌های ماژولار:** کدهای بزرگ را به کامپوننت‌های کوچک‌تر و قابل استفاده مجدد در دایرکتوری `components/` تقسیم کنید.
*   **استایل‌دهی استاندارد:** فقط از کلاس‌های Tailwind CSS استفاده کرده و از نوشتن استایل‌های درون‌خطی (Inline Styles) پرهیز کنید.
*   **مدیریت وضعیت:** برای وضعیت‌های محلی از `useState` و برای هماهنگی داده‌های عمومی سیستم از `Context`های ایجاد شده در `context/` استفاده کنید.

## 🧪 تست و پایداری کدهای جدید
*   هر زمان که تغییری در منطق تجاری سیستم (خصوصاً در بخش بک‌اند) ایجاد کردید، حتماً تست‌های واحد مربوطه را در پوشه `backend/tests/` بررسی کرده و اجرا کنید.
*   دستور اجرای تست‌ها:
    ```bash
    npm test --prefix backend
    ```
*   اگر قابلیت جدیدی اضافه می‌کنید، نوشتن تست واحد مناسب برای آن به شدت توصیه می‌شود.
